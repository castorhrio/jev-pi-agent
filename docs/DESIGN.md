# 视觉 token 的具名出处

**这份文档是视觉 token 的登记册（register），不是设计说明。** 它回答一个问题：
屏幕上每一个字号、圆角、边线宽度、颜色，**叫什么、值是多少、用在哪、为什么是这个值**。

## 为什么需要它

`apps/desktop/src/renderer/src/styles.css` 的 `:root` 里已经有 token，字号档甚至已经被
`tests/contract/typography.test.ts` 钉成「四档、不许第五档」。但**圆角、边线宽度、颜色分配**
从来没有一处具名出处：

- 圆角在规则里散着写：`0`、`2px`、`3px`、`4px`、`6px`、`7px`、`10px`、`999px`、`50%`。
  其中只有三个有名字（`--r-sm` / `--r` / `--r-lg`），其余是裸值。裸值的问题不是难看，
  是**下一个值不需要任何决定就能写进去**——`border-radius: 5px` 编译得过、门禁全绿、
  屏幕上多一档没人认领的圆角。字号档当初就是这么烂掉的（47 条规则、九个值）。
- 边线宽度同理：`1px` 是发丝边，`2px` 只该出现在两处（强调条与滚动条滑块），
  但「只该出现在两处」这句话此前只活在写 CSS 的人脑子里。
- 颜色有 `--accent` / `--ok` / `--warn` / `--err` / `--info` 这些名字，也有
  「蓝=可交互、绿=成功、琥珀=注意、红=失败，别的都不上色」这条规则，
  但规则写在 `styles.css` 顶部的注释里，注释不是门禁。

所以这份文档是**具名出处**，`:root` 是它的机器副本，`tests/contract/design-tokens.test.ts`
是两者之间的那条链。CSS 不能 `@import` 一份 markdown，所以「引用」在这里的落地方式就是
**门禁**：文档里没有的值，样式表里不许出现；样式表里没有的值，文档里不许留着。

## 怎么改

1. 先在这份文档里加一行（值、用在哪、为什么），
2. 再改 `styles.css`，
3. `npx vitest run tests/contract/design-tokens.test.ts` 必须绿。

反过来做（先写 CSS 再补文档）也可以，只是中间那一步是红的——这正是它存在的意义：
**一个新值是一次决定，不是一次输入**。

---

## 字号档（type scale）

四档，加一条地板。`tests/contract/typography.test.ts` 钉住「每条 `font-size` 都是
`var(--fs-…)`」与「解析后最多四个尺寸」；这张表钉住「文档与 `:root` 说的是同一个数」。

| token | 值 | 角色 |
|---|---|---|
| `--fs-display` | `18px` | 面板标题，一屏一次 |
| `--fs-body` | `13px` | 正文、输入框、输入区 |
| `--fs-note` | `var(--fs-min-cjk)` | 次级正文、表格、代码、标签 |
| `--fs-fine` | `10.5px` | 仅 ASCII 铬件：键帽、计数、箭头、步骤号 |
| `--fs-min-cjk` | `12px` | 中文下限。不是角色，是地板：汉字在 10.5px 会糊成灰块 |

`--fs-note` 与 `--fs-min-cjk` 是同一个数，这是有意的：note 是中文最常落的角色，
它不可能掉到地板下面。`--fs-fine` 是唯一允许低于地板的角色，因为它只排 ASCII。

## 圆角（radius register）

| 值 | token | 用在哪 | 为什么 |
|---|---|---|---|
| `0` | — | 表格行、分段控件、贴边面板 | 贴边的东西有圆角就会露出底下的缝 |
| `2px` | — | 进度条/计量条、标签页顶角 | 4px 高的条上，2px 已经是半个圆 |
| `3px` | — | 品牌标、行内小输入、小按钮 | 15px 见方的盒子上，4px 会吃掉一半 |
| `4px` | `--r-sm` | 按钮、输入框、卡片内控件 | 控件档：手指/光标落点的那一层 |
| `6px` | — | 滚动条滑块 | 滑块是 10px 宽，圆角要跟着它走 |
| `7px` | `--r` | 卡片、面板 | 表面档：一块内容的外轮廓 |
| `10px` | `--r-lg` | 对话框、最大表面 | 浮在一切之上的那一层，圆角最大 |
| `999px` | — | 药丸徽章、选择器 | 「药丸」不是半径，是形状：任何高度都全圆 |
| `50%` | — | 状态点、步骤号 | 圆，不是圆角：正方形盒子的内切圆 |

**为什么不是「四档圆角」**：字号能收成四档，是因为同一个角色在不同面板上必须一样大；
圆角不是——一个 4px 高的进度条和一个 400px 宽的对话框，圆角的**物理尺寸**本来就该不同。
所以这里登记的是「每个值对应一种盒子」，而不是「一个尺度」。门禁因此断言的是
**登记册与样式表的值集合相等**，不是「值的个数 ≤ 4」。

## 发丝边（hairline）

| 宽度 | 用在哪 | 为什么 |
|---|---|---|
| `1px` | 所有分隔线、卡片边、输入框边、表格线 | 发丝边：在 1x 屏上是一条线，在 2x 屏上是两条物理像素，不会变成一条灰带 |
| `2px` | 只有两处：`border-left` 的强调条（激活/警告/强边），以及 `::-webkit-scrollbar-thumb` | 强调条是**状态**不是分隔，它要比发丝边粗一档才看得见；滑块同理，它要压住轨道 |
| `0` | 重置 | 浏览器默认边框不是设计的一部分 |
| `none` | 重置 | 同上，写 `none` 的地方是「这条边不该存在」 |

门禁断言：样式表里出现的每个边线宽度都在这张表里；`2px` 只允许出现在
`border-left` 或 `::-webkit-scrollbar-thumb` 上。**加第三处 2px 边线是红的**，
因为那意味着「强调」这个词被用在了第二个意思上。

## 铬色与强调色（colour roles）

规则只有一句：**颜色承载意义，不承载装饰。** 蓝=可交互，绿=成功，琥珀=注意，红=失败，
其余一切都是中性灰。`tests/contract/contrast.test.ts` 钉住对比度，
这张表钉住「每个颜色 token 都有名字、有值、有角色」。

| token | 值 | 角色 |
|---|---|---|
| `--bg` | `#0a0a0b` | 画布。真黑，不是深灰：长时间盯着的底色不该有色调 |
| `--surface` | `#101012` | 一级表面：面板 |
| `--surface-2` | `#17171a` | 二级表面：面板里的块 |
| `--surface-3` | `#1d1d21` | 三级表面：块里的块、轨道 |
| `--inset` | `#08080a` | 凹进去的表面：代码块、输入区 |
| `--border` | `#232327` | 发丝边 |
| `--border-soft` | `#1a1a1e` | 更弱的分隔：同级之间的线 |
| `--border-strong` | `#34343b` | 强边：需要被看见的轮廓 |
| `--text` | `#ecedee` | 正文 |
| `--text-2` | `#9a9aa4` | 次级正文 |
| `--text-3` | `#81818c` | 三级文字：元信息、时间戳。已提到 4.6:1 |

| `--add` | `#2ea043` | diff 新增 |
| `--del` | `#f85149` | diff 删除。与 `--err` 同值是有意的：删除不是错误，但它是同一族的红 |

## 什么不是 token

- **间距**（`--sp-1..5`）与**布局尺寸**（`--page-w`、`--rail-w`、`--measure-prose` 等）
  已经在 `:root` 里有名字，由 `tests/contract/layout.test.ts` 的几何断言管着，
  不在这份登记册里重复一遍。
- **字体栈**（`--sans` / `--mono`）由 `tests/contract/typography.test.ts` 与
  `tests/contract/layout.test.ts` 的计算值断言管着（Latin → 中文 → generic 的顺序、
  无假斜体），同样不在这里重复。
- **一次性的几何**（某个表格列的宽度、某个定位菜单的坐标）不是 token，也不该是。

## 这份文档做不到什么

它证明不了「这个圆角好看」。它证明的是：**屏幕上出现的每一个值，都有人认领过**。
观感仍然要人看——`docs/state-walkthrough.md` 是那件事的入口。
