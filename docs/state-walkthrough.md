# 五个界面状态的观感走查

这份文件是**给下一个人**的，不是给写它的人的。

`docs/manual-verification.md` 步骤 6 一直写着同一句话：五个界面状态被断言过、被测量过、被拍过照，
但**没有人看过并说它们读起来像首启 / 像失败 / 像权限请求**。这句话之所以能挂好几轮，是因为它没有
下一步——「去看一眼」不是一件可以交接的事。这里把它变成一件可以交接的事：每个状态三条**能用「是 / 否」
回答**的判据，每个状态**两个尺寸**的图，加一张**签了字才算数**的记录表。

## 为什么机器判不了这一半

已经有的三道门禁各自回答一个问题，都不回答「读起来对不对」：

| 门禁 | 它回答的问题 | 它回答不了的问题 |
|---|---|---|
| `tests/e2e/scenarios.e2e.test.tsx` | 该有的字在不在屏上、不该有的在不在 | 这些字**排在一起**读起来像不像首启 |
| `tests/contract/layout.test.ts` | 不横向溢出、不塌缩、不裁字、不压字、控件不出屏 | 引导语够不够醒目、失败信息压不压过内容 |
| `tests/contract/screenshots.test.ts` | 图与渲染层源码同步、尺寸等于开窗尺寸 | 图里那一眼看到的东西对不对 |

三条全绿而屏幕仍然难读，是完全可能的：一个段落可以每条几何规则都过，读起来还是一堵墙。
所以这一半只能由人回答——但「由人回答」不等于「随便看看」，判据写死在这里，答案只有是 / 否。

## 5 分钟走查脚本

十张图，按顺序看，每张图回答它那一态的三条判据（判据在下面 `## 判据` 里，每条都锚在屏幕上真的会
出现的字上）。**答「否」就停在那一条**，把屏幕上看到的东西记进记录表，不要顺手修——一边改行为一边
下结论，等于把证据和结论混在一起，下一个人无法复现你看到的那一屏。

两个尺寸都要看，因为它们是两个不同的问题：1440×900 是产品开窗的尺寸（「正常窗口下读起来对不对」），
768×700 是产品允许的最小窗口（「挤到最小时还读不读得下去」）。窄窗口那一列多问一句：
**有没有横向滚动条、有没有字被截成半行**——这是几何门禁量得到的那一半，人眼只需确认它没有骗人。

| # | 图 | 尺寸 | 这一张要回答的 |
|---|---|---|---|
| 1 | `docs/screenshots/empty.png` | 1440×900 | `empty` 的三条判据 |
| 2 | `docs/screenshots/states/empty-768x700.png` | 768×700 | 同上，另加：引导语与三步没有被挤到折叠线以下 |
| 3 | `docs/screenshots/states/loading.png` | 1440×900 | `loading` 的三条判据 |
| 4 | `docs/screenshots/states/loading-768x700.png` | 768×700 | 同上，另加：两处「加载中…」都还在屏上 |
| 5 | `docs/screenshots/error.png` | 1440×900 | `error` 的三条判据 |
| 6 | `docs/screenshots/states/error-768x700.png` | 768×700 | 同上，另加：`重试` 按钮仍在折叠线以上 |
| 7 | `docs/screenshots/states/partial.png` | 1440×900 | `partial` 的三条判据 |
| 8 | `docs/screenshots/states/partial-768x700.png` | 768×700 | 同上，另加：失败原因没有被截断到看不见 |
| 9 | `docs/screenshots/states/permission.png` | 1440×900 | `permission` 的三条判据 |
| 10 | `docs/screenshots/states/permission-768x700.png` | 768×700 | 同上，另加：弹窗五件与四个回答在窄窗口下仍分得清 |

看完把这一行填进文末的记录表（`YYYY-MM-DD` 换成当天日期；**第一列是日期的那一行就是签字**）：

```
| YYYY-MM-DD | 你的名字 | 10 张（五态 × 两个尺寸） | 15 条全满足 / 第 N 条不满足 | 无 / <屏幕上看到什么> | 五态判据全满足 / 第 N 条不满足：<屏幕上看到什么> |
```

这十张图是布局门禁在真实 Chromium 里拍的，不是手绘也不是 mock：`npm test` 的
`tests/contract/layout.test.ts` 把每个 target 的截图写进 `.run-logs/layout/`（该目录被忽略），
上面十张是从那里挑出来提交的，所以**任何人重跑一次都能得到同一批图**。

这十张也都在 `docs/screenshots/sources.json` 里记着哈希，所以
`node scripts/screenshot-sources.mjs --check` 说 PASS 时，它量的是**这十张**（连同另外四张）
还对着当前的渲染层源码——不是「某个目录里的图还行」。这句话以前只是巧合：清单和记账是两份
列表，谁也没核对它们是不是同一份。现在 `tests/contract/state-walkthrough.test.ts` 逐张核对
「上面这张表点名的每个文件都在 `sources.json` 的 `screenshots` 键里」，所以往走查清单里加一张
没被记账的图会当场打红，而不是让 `--check` 继续对另一批文件说 PASS。

`loading` 那两张挑的是**读取还没返回的那一帧**（`.run-logs/layout/loading-frame.png` 与
`loading-frame-tight.png`），不是 `state-loading*` 那两张。原因写在 `dev/scenarios.ts` 里：
`?scenario=loading` 只是把每一次读取往后推迟，所以这一态 settle 之后的画面就是普通的首屏。
这一轮把这两句话都变成了量出来的数——settle 后的加载态与已加载的应用逐字节相同，而入库那两张
一旦等于「已加载」那一帧就是红。挑错文件不再靠人记得，重拍的人当场会被指名。

`tests/contract/state-walkthrough.test.ts` 钉住三件事：每一态的两张图都在仓库里、窄窗口那张的像素尺寸
等于 `bootstrap.ts` 声明的 `minWidth`/`minHeight`、以及上面这张表按顺序列全了十张图。

## 怎么走（两条路，选一条）

1. **有应用**：`npm run dev:web`，按下面五节给的 URL 依次打开，并把窗口拖到 768×700 再看一遍。
   这是唯一能看到交互（点「拒绝」之后弹窗消失）的路。
2. **只有图**：直接看上面那十张图，不必装应用、不必联网。这就是「远程可做」的意思——
   把图发给任何一个人，他就能回答下面这些问题。

两条路都**不改代码**。走查途中发现缺陷就记进记录表，不要顺手修。

## 判据

每个状态三条。**任何一条答「否」就是缺陷**，记进记录表，不要在这一轮修。
判据里反引号包住的是屏幕上真的会出现的字（取自 `apps/desktop/src/shared/i18n.ts`），
照着找，不要凭印象。

### empty

- 图：`docs/screenshots/empty.png`（1440×900）· 窄窗口：`docs/screenshots/states/empty-768x700.png`（768×700）· URL：`?scenario=empty`
- 判据：
  - [ ] 第一眼落在 `还没有对话。在下方描述你的任务，Agent 会先构建上下文再开始工作。` 上，
        而不是落在空列表或列头上——引导语在折叠线以上，且比周围文字更醒目。
  - [ ] `发送之后会发生什么` 下面的三步**一眼能数出三步**，读完知道第一步要做什么，
        而不是一段读不完的散文。
  - [ ] 屏幕上**没有** `加载中…`：已经加载完就不许再声称在加载。
- 不合格长什么样：空白页；引导语被挤到折叠线以下；三步写成一段；已经加载完还在转圈。
- 依据：`tests/e2e/scenarios.e2e.test.tsx` 的 empty 一组断言。

### loading

- 图：`docs/screenshots/states/loading.png`（1440×900）· 窄窗口：`docs/screenshots/states/loading-768x700.png`（768×700）· URL：`?scenario=loading`
- 判据：
  - [ ] 会话列与对话区**都在说** `加载中…`，两处一致——一处说加载、另一处说「没有」是最糟的组合。
  - [ ] 屏幕上**没有** `还没有对话`：把还没读到的历史渲染成「空」，是对未到达的数据下确定结论。
  - [ ] 加载态看起来是**在等**，不是**坏了**：没有错误色、没有 `重试` 按钮、没有空白面板。
- 不合格长什么样：出现「还没有对话」；骨架闪一下就变成空面板；加载态被画成错误态。
- 依据：`tests/e2e/scenarios.e2e.test.tsx` 的 loading 一组断言（在读取尚未返回的那一帧拍照）。

### error

- 图：`docs/screenshots/error.png`（1440×900）· 窄窗口：`docs/screenshots/states/error-768x700.png`（768×700）· URL：`?scenario=error`
- 判据：
  - [ ] 标题 `出错了` 之后**紧接着**是原始失败文本 `[fixture:error] workspace.listRecent failed`，
        不是一句「出错了」就结束——用户要能把这行字贴给别人。
  - [ ] `重试` 按钮是这一屏上**最显眼的动作**，不需要滚动就能看到。
  - [ ] 失败信息**没有压过**它要解释的东西：`出错了` 与那行原因之间没有大段空白或装饰把两者拆开。
- 不合格长什么样：只有一句「出错了」没有原因；空面板；重试按钮在折叠线以下；错误页把整个窗口涂成红色。
- 依据：`tests/e2e/scenarios.e2e.test.tsx` 的 error 一组断言。

### partial

- 图：`docs/screenshots/states/partial.png`（1440×900）· 窄窗口：`docs/screenshots/states/partial-768x700.png`（768×700）· URL：`?scenario=partial`
- 判据：
  - [ ] 项目名 `jev-pi-agent` **还在屏上**：一个面板读失败，不该把读成功的部分一起抹掉。
  - [ ] 会话列说的是 `会话列表读取失败（不是空的）` 并带原因 `[fixture:partial] sessions.list failed`，
        而不是「没有会话」——后者会让用户以为数据没了。
  - [ ] 读起来像**一次局部故障**，不像整页错误：`会话列表读取失败（不是空的）` 只出现在坏掉的那一列，好的那几列照常可读。
- 不合格长什么样：把读失败渲染成「没有会话」；整页变成错误页；失败原因被截断到看不见。
- 依据：`tests/e2e/scenarios.e2e.test.tsx` 的 partial 一组断言。

### permission

- 图：`docs/screenshots/states/permission.png`（1440×900）· 窄窗口：`docs/screenshots/states/permission-768x700.png`（768×700）· URL：`?scenario=permission`
- 判据：
  - [ ] 弹窗标题 `Agent 请求权限` 之后，五件东西**都能读**：类别 `SHELL`、风险 `high`、资源、命令、原因——
        缺一件，用户就只能盲点。
  - [ ] 四个回答**都在**且分得清：`允许一次` / `本次会话允许` / `本项目允许` / `拒绝`，
        其中 `拒绝` 不比允许更难找（不藏在二级菜单里、不是灰色小字）。
  - [ ] 以 `Agent 请求权限` 为标题的弹窗**盖住**了背后的对话而不是挤在旁边：模态就该是模态，背后的内容不该还在抢注意力。
- 不合格长什么样：只有「允许」没有「拒绝」；五件里缺一件；四个回答挤成一行分不清；
  弹窗看起来像页面里的一块普通卡片。
- 依据：`tests/e2e/scenarios.e2e.test.tsx` 的 permission 一组断言；
  `tests/contract/layout.test.ts` 的 `state-permission` / `state-permission-tight` 两条 target。

## 记录（走查人填，只追加）

一行一次走查。`结论` 写「五态判据全满足」或「第 N 条不满足：<屏幕上看到什么>」——
写「OK」不算记录。四列是必须的，缺一列这张表就不成立：`日期`（签字）、`走查人`（谁说的）、
`看了哪几张`（看了几张就答几条，没看全的那一态不算走过）、`结论`（是 / 否，不是「还行」）。

**第一列写了日期的一行，就是一次签字。** 签字之后，`README.md` 中英两半里那句
「五个界面状态还没有被人眼走查过」必须同时改掉，并且**带上同一个日期字面量**——
不是「都带日期」，是**三处（这张表、英文那半、中文那半）写的是同一串 `YYYY-MM-DD`**。
两半各写一个不同日期，等于两次走查只签了一次，下一个人无法判断哪一次是真的。

`tests/contract/state-walkthrough.test.ts` 三个方向都会打红：表里有日期而 README 没改、
README 改了而表里没日期、以及**两处日期不是同一个字面量**。

| 日期 | 走查人 | 看了哪几张 | 五态判据 | 不合格项 | 结论 |
|---|---|---|---|---|---|
| — | — | — | — | — | **未走查**：判据已就位，等一个人按上面五节逐条回答 |

## 还没有人签：这一节写清等谁、什么时候、看哪十张

上面那一行仍然写着 `—`，`README.md` 中英两半也仍然写着这五个状态没被人眼走查过。这一轮没有一个
可以派的人，所以这里不写「尚未走查」——那句话在这份文件开头已经挂了好几轮，它没有下一步——
而把下一步写成三个答得出来的问题。

- **等谁**：愿意看十张 PNG 的人就够了。这一条不需要装应用、不需要 `contents: write` 令牌、不需要
  Windows 机器；把上面十张图发给任何人，他就能答。第一顺位是仓库所有者 `castorhrio`，因为初审答辩
  时那句「这一屏我看过」必须由站在评审面前的人自己说。
- **什么时候**：初审答辩之前，**一次答完十五问**。分两天各答一半，那张表读不出到底发生了什么，
  而「读不出」正是这一页要替换掉的东西。
- **看哪十张**：就是上面 `## 5 分钟走查脚本` 那张表按顺序列的十张，五态各两个尺寸——宽的那张是
  产品开窗的尺寸，窄的那张是产品允许的最小窗口。少看一态，那一态就不算走过。

答完之后要动三个地方，少动一个都会红：记录表追加一行（第一列那个日期就是签字）、`README.md`
中英两半那句话改成同一个日期字面量、`docs/dod-status.md` 里「权限门不可绕」一行的「还差什么」
改成已走查并带上同一个日期。

**这一节不是签字。** 它的第一列没有日期，也不该有：判据、图、路径都就位而没人回答，缺的就是
「一个人给出的是 / 否」，代签会把这一页变成又一份机器打绿的自我证明。

## 这份文件不判什么

- **不判颜色对比度**：那是 `tests/contract/contrast.test.ts` 的事，量的是比值，不是观感。
- **不判几何**：不横向溢出、不塌缩、不裁字、不压字由 `tests/contract/layout.test.ts` 在两个窗口尺寸上量。
- **不判文案对不对**：判据里引用的字取自 `i18n.ts`，改文案会让判据读起来对不上——那时该改的是这份文件，
  不是把判据放宽。
- **不判「好看」**：三条判据问的都是「读起来像不像它自称的那个状态」，不是审美偏好。
