# 五个界面状态的观感走查

这份文件是**给下一个人**的，不是给写它的人的。

`docs/manual-verification.md` 步骤 6 一直写着同一句话：五个界面状态被断言过、被测量过、被拍过照，
但**没有人看过并说它们读起来像首启 / 像失败 / 像权限请求**。这句话之所以能挂好几轮，是因为它没有
下一步——「去看一眼」不是一件可以交接的事。这里把它变成一件可以交接的事：每个状态三条**能用「是 / 否」
回答**的判据，每个状态**两个尺寸**的图，加一张**签了字才算数**的记录表。

## 为什么机器判不了这一半

已经有的三道门禁各自回答一个问题，都不回答「读起来对不对」：

| 门禁 | 它回答的问题 | 它回答不了的问题 |
|---|---|---|
| `tests/e2e/scenarios.e2e.test.tsx` | 该有的字在不在屏上、不该有的在不在 | 这些字**排在一起**读起来像不像首启 |
| `tests/contract/layout.test.ts` | 不横向溢出、不塌缩、不裁字、不压字、控件不出屏 | 引导语够不够醒目、失败信息压不压过内容 |
| `tests/contract/screenshots.test.ts` | 图与渲染层源码同步、尺寸等于开窗尺寸 | 图里那一眼看到的东西对不对 |

三条全绿而屏幕仍然难读，是完全可能的：一个段落可以每条几何规则都过，读起来还是一堵墙。
所以这一半只能由人回答——但「由人回答」不等于「随便看看」，判据写死在这里，答案只有是 / 否。

## 5 分钟走查脚本

十张图，按顺序看，每张图回答它那一态的全部判据（`error` 四条，其余四态各三条；判据在下面 `## 判据` 里，
每条都锚在屏幕上真的会出现的字上）。**答「否」就停在那一条**，把屏幕上看到的东西记进记录表，
不要顺手修——一边改行为一边下结论，等于把证据和结论混在一起，下一个人无法复现你看到的那一屏。

两个尺寸都要看，因为它们是两个不同的问题：1440×900 是产品开窗的尺寸（「正常窗口下读起来对不对」），
768×700 是产品允许的最小窗口（「挤到最小时还读不读得下去」）。窄窗口那一列多问一句：
**有没有横向滚动条、有没有字被截成半行**——这是几何门禁量得到的那一半，人眼只需确认它没有骗人。

这十张图是布局门禁在真实 Chromium 里拍的，不是手绘也不是 mock：`npm test` 的

没被记账的图会当场打红，而不是让 `--check` 继续对另一批文件说 PASS。

`loading` 那两张挑的是**读取还没返回的那一帧**（`.run-logs/layout/loading-frame.png` 与
`loading-frame-tight.png`），不是 `state-loading*` 那两张。原因写在 `dev/scenarios.ts` 里：
`?scenario=loading` 只是把每一次读取往后推迟，所以这一态 settle 之后的画面就是普通的首屏。

一旦等于「已加载」那一帧就是红。挑错文件不再靠人记得，重拍的人当场会被指名。

`tests/contract/state-walkthrough.test.ts` 钉住三件事：每一态的两张图都在仓库里、窄窗口那张的像素尺寸
等于 `bootstrap.ts` 声明的 `minWidth`/`minHeight`、以及上面这张表按顺序列全了十张图。

## 10 分钟速查表：十张图 × 三十二问

上面那张表说「这一张要回答哪几条判据」，这一张是**答题纸**：三十二行，一行一问，答完就是一次走查。
判据原文在下面 `## 判据` 一节——判据是**十六条**（五态，其中 `error` 四条、其余每态三条），而每一条要在
**两张图**上各答一遍（宽窗口一张、最小窗口一张），所以答题纸是**三十二行**。这里的每一问都是它标的那条
判据里的原话，`tests/contract/state-walkthrough.test.ts` 逐行核对「这一问确实出自它标的那条判据」：
判据改了而这张表没改，会当场指名是哪一行，而不是让下一个人照着答一份对不上的题。

**只许答三个字：`是` / `否` / `说不清`。** 答「说不清」按**未过**算——说不清就是这一屏没让人看懂，
和「否」一样要记进记录表，区别只是记的时候写清「哪一句说不清」。不许写「还行」「基本可以」：
那不是答案，是把判断推给下一个人。

## 怎么走（两条路，选一条）

1. **有应用**：`npm run dev:web`，按下面五节给的 URL 依次打开，并把窗口拖到 768×700 再看一遍。
   这是唯一能看到交互（点「拒绝」之后弹窗消失）的路。
2. **只有图**：直接看上面那十张图，不必装应用、不必联网。这就是「远程可做」的意思——
   把图发给任何一个人，他就能回答下面这些问题。

两条路都**不改代码**。走查途中发现缺陷就记进记录表，不要顺手修。

## 怎么把十张图 + 判据发给一个没装应用的人

上面第二条路（「只有图」）是这一页唯一能远程完成的一半，而它一直缺最后一步：**怎么把图交出去**。
「把图发给他」不是一条指令——十张图散在两个目录里，靠人从上面那张表里抄路径，抄漏一张就是少走一态，
而少走一态的那一行仍然会被签成「五态判据全满足」。所以这一步现在是一条命令，列表从上面那张表里读，
不是另抄一份：

```bash
node scripts/screenshot-sources.mjs --walkthrough
```

它把十张图的路径按走查顺序打到 stdout（一行一个，别的什么都不打），并在 stderr 说一句
`walkthrough: 10 image(s), all recorded in docs/screenshots/sources.json`。**stdout 只有路径**，
所以打包也是一条命令：

```bash
tar -czf walkthrough.tar.gz $(node scripts/screenshot-sources.mjs --walkthrough)
```

它退出 1 的两种情形都要当真：`docs/state-walkthrough.md` 里那张表没了（没有可交的清单），
或者清单里有一张图不在 `docs/screenshots/sources.json` 里（stderr 上是 `[unrecorded] …`）——
后者意味着 `node scripts/screenshot-sources.mjs --check` 说不出这张图还是当前屏幕，
交出去的是一张没人核过的图。

发出去的是三样东西，缺一样对方就答不完：

1. **`walkthrough.tar.gz`**：十张图，五态 × 两个尺寸，顺序就是上面那张表的顺序；
2. **这一页的 `## 判据` 一节**：十六条问（`error` 四条，其余四态各三条），每条只有是 / 否，
   判据里反引号包住的字就是屏幕上要找的字（每问在两张图上各答一遍，所以答题纸是
   `## 10 分钟速查表` 那三十二行）；
3. **下面这个回执模板**：他答完照着填，把这两行发回来。第一行是列头，与文末记录表的列头
   **逐字相同**——不是「差不多」，是同一串字（`tests/contract/state-walkthrough.test.ts` 逐格比对，
   改一处不改另一处会当场红）；第二行是占位，`YYYY-MM-DD` 换成当天日期。

```
| 日期 | 走查人 | 看了哪几张 | 五态判据 | 不合格项 | 结论 |
|---|---|---|---|---|---|
| YYYY-MM-DD | 你的名字 | 10 张（五态 × 两个尺寸） | 32 条全满足 / 第 N 条不满足 | 无 / <屏幕上看到什么> | 五态判据全满足 / 第 N 条不满足：<屏幕上看到什么> |
```

对方不需要装应用、不需要令牌、不需要 Windows 机器、不需要联网——他只需要打开十张图，逐条回答是 / 否。
答完把那一行发回来，收到的人做三件事（少一件门禁会红）：把日期填进文末记录表的第一列、
`README.md` 中英两半那句话改成同一个日期字面量、`docs/dod-status.md` 里「权限门不可绕」一行的
「还差什么」改成已走查并带上同一个日期。

**这一节不是签字。** 它只把「发给谁、发什么、怎么发回来」写成一条命令加三样东西；
签字仍然是文末记录表第一列的那个日期，而那个日期只能由看过十张图的人给出。

## 判据

每个状态三条。**任何一条答「否」就是缺陷**，记进记录表，不要在这一轮修。
判据里反引号包住的是屏幕上真的会出现的字（取自 `apps/desktop/src/shared/i18n.ts`），
照着找，不要凭印象。

**这句话现在是一条会红的门禁，不是一句约定。** 每条判据至少要引用一个 `i18n.ts` 里真的有的
字符串（`tests/contract/state-walkthrough.test.ts` 逐条比对）；改掉 `empty.chat` 这类文案而
没改判据，那条判据会当场被指名，而不是让下一个人照着找一段屏幕上已经没有的字。判据里也有
不是文案的字——`jev-pi-agent` 是项目名、`SHELL` / `high` 是权限类别与风险档、
`[fixture:error] …` 是夹具的失败原文——它们不是散文，字典里本来就不该有，所以规则是
「至少一条是字典里的文案」，不是「每一条都是」。

### empty

- 图：`docs/screenshots/empty.png`（1440×900）· 窄窗口：`docs/screenshots/states/empty-768x700.png`（768×700）· URL：`?scenario=empty`
- 判据：
  - [ ] 第一眼落在 `还没有对话。在下面说清要做什么，Agent 会先看一遍项目再动手。` 上，
        而不是落在空列表或列头上——引导语在折叠线以上，且比周围文字更醒目。
  - [ ] `发送之后会发生什么` 下面的三步**一眼能数出三步**，读完知道第一步要做什么，
        而不是一段读不完的散文。
  - [ ] 屏幕上**没有** `加载中…`：已经加载完就不许再声称在加载。
- 不合格长什么样：空白页；引导语被挤到折叠线以下；三步写成一段；已经加载完还在转圈。
- 依据：`tests/e2e/scenarios.e2e.test.tsx` 的 empty 一组断言。

### loading

- 图：`docs/screenshots/states/loading.png`（1440×900）· 窄窗口：`docs/screenshots/states/loading-768x700.png`（768×700）· URL：`?scenario=loading`
- 判据：
  - [ ] 会话列与对话区**都在说** `加载中…`，两处一致——一处说加载、另一处说「没有」是最糟的组合。
  - [ ] 屏幕上**没有** `还没有对话`：把还没读到的历史渲染成「空」，是对未到达的数据下确定结论。
  - [ ] 加载态看起来是**在等**，不是**坏了**：没有错误色、没有 `重试` 按钮、没有空白面板。
- 不合格长什么样：出现「还没有对话」；骨架闪一下就变成空面板；加载态被画成错误态。

## 这份文件不判什么

- **不判颜色对比度**：那是 `tests/contract/contrast.test.ts` 的事，量的是比值，不是观感。
- **不判几何**：不横向溢出、不塌缩、不裁字、不压字由 `tests/contract/layout.test.ts` 在两个窗口尺寸上量。
- **不判文案对不对**：判据里引用的字取自 `i18n.ts`，改文案会让判据读起来对不上——那时该改的是这份文件，
  不是把判据放宽。**这一条已经由门禁接管**：`tests/contract/state-walkthrough.test.ts` 把每条判据
  引用的散文与字典逐条比对，改文案而没改判据会红，并指名是哪一态的第几条。门禁判不了的是
  「这段文案读起来对不对」——那仍然只能由人回答。
- **不判「好看」**：判据问的都是「读起来像不像它自称的那个状态」，不是审美偏好。
